# spec-lint

> 需求文档的质量门禁——像 ESLint 检查代码那样检查一份需求文档。只评审，不代写。

## 它是什么

spec-lint 是一个**评审需求文档的 agent 技能**。

写代码有编译器、有 lint、有测试；写需求文档只有评审会，而评审会靠的是当场的注意力——
大家看一遍，说几句，散会。文档里哪句话说不清、哪个指标其实无法度量、
哪两处自相矛盾、哪条关键假设没有依据，很容易就这么过去了。

spec-lint 补的是这一侧：把"评审"从一次性的会议，变成能反复跑、能对账的检查。

它**只评审，不代写**——输出的永远是一张质疑清单，不是一份改好的文档。

## 它做什么

给你一张**质疑清单**，每条都带三样东西：

- **规则编号**——比如 `B1`。有编号才能记账："这条我不认同，以后别再报"
- **原文引用**——逐字引用文档原句并标出行号。找不到原句的质疑不允许上报
- **请作者回答的问题**——不是"建议优化"，是填空题

举个例子：

> 🔴 **B1** 模糊形容词无度量主体
> 原文：「显著提升新用户的上手效率」
> 请回答：对应的指标、基线值、目标值、采集方式各是什么？

结果分三级：🔴 开发/评审前必须回答、🟡 大概率返工、🔵 表述问题，
外加一句话结论——**这份文档当前能不能进入研发评审**。

## 用在哪些场景

**一、手里已经有一份文档。**
把 PRD、产品设计文档或调研报告交给它评审。这是最基本的用法。

**二、文档还在起草，或者正和 AI 一起生成。**
反复用：评审 → 作者修订 → 复评。每轮只查两件事——上一轮的问题解决了没、
这轮改动有没有带出新问题。收敛的信号是**本轮「新出现」为 0**，
而不是"没有问题"：问题永远挑得出来，永远能挑。

**三、需求还只是想法，文档根本不存在。**
它不掉头走人。把每条规则反过来，就是一份**开工前必答清单**：
"这个功能的价值用什么数字衡量""本期明确不做什么""出问题怎么退回去"。
**清单由它印，怎么问、怎么追问交给上游的对话流程**——它只保证该问的没漏。

**四、接进开发流水线。**
放在 Spec 定稿与写实施计划之间当闸门：上游负责问清楚，它负责查漏，
下游负责排计划、写代码。（比如接进 OpenSpec：把门禁写进提案规则，
提案过不了门就不解锁任务。）

## 原理

**规则库是核心资产。** 31 条活跃规则分七组，另有 3 条合并别名；按体裁和文档模式分流：独立完整版、增量版、合并版分别适用不同的完整性边界。产品需求按"可验收性"评，
调研 / 可行性文档按"决策就绪度"评，两套标准不混用。

每条规则都标注出处——IEEE 830、spec-kit 的 clarify 分类法、
OpenSpec 的 SHALL / WHEN-THEN 约定、Amazon PR/FAQ，
以及**从真实项目的返工里反推出来的校准规则**。最后这一类别处拿不到：
它不是从书上抄的，是从"这份文档哪里让人返了工"长出来的。

**两层检查。** 机械扫描负责能确定性判断的部分（占位残留、开放列举、
弱模态、"和/或"），给出带行号的证据；语义判断负责其余部分——状态机完不完备、
非功能维度交代了没、经济假设能不能复算。机械结果不替代判断，
只是把确定的部分先钉死。

**证据强制。** 每条结论都必须能指回原文，编造的、找不到原句的质疑会被直接拒绝。
这不只是要求评审者守规矩——工具本身会核对。

**跨轮次能对上号。** 每条问题有一个稳定指纹，只依赖规则编号和违规内容，不依赖行号。
所以文档改了措辞、行号漂移之后，上一轮的问题和这一轮的发现仍然能配对。
这是"评审"能变成"循环"的前提。

## 它不做什么

- **不评分、不排名、不代写、不评价"该不该做这个功能"。**
  它只保证决策依据是显形的、可度量的、自洽的。
- **它是一张网，不是一堵墙。** 31 条活跃规则里能确定性判断的只是一小部分，
  其余依赖阅读和判断。它帮你别漏，不替你决定。
- **门禁是判断级的。** 编号、证据、指纹让结论可追溯，
  但"够不够格开工"仍然由人和流程确认。

## 开始用

它是一个技能，把 `spec-lint/` 放进你所用的 agent 技能目录即可：

| 宿主 | 技能目录 |
|---|---|
| Codex | `~/.codex/skills/` |
| Claude Code | `~/.claude/skills/` |
| DeepSeek Harness | `$DSH_HOME/skills/`（默认 `~/.dsh/skills/`） |

也可以从 Releases 下载压缩包，解压后放进技能目录（不联网、不用 git）。

然后在 agent 里说话就行：

- "用 spec-lint 评审这份 PRD"
- "用 spec-lint 给个门禁判定"
- "用 spec-lint 复评，看上一轮的问题解决了没"
- "这份需求还没成文，帮我列出开工前必须回答的问题"

不联网、不需要安装任何依赖。
