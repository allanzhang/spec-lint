# 报告格式

评审报告用中文输出，严格按以下结构。Blocker 全部是"请回答"式填空题。

```markdown
# Spec 评审报告：<文档标题>

## 摘要
- 🔴 <n> 项必须回答 · 🟡 <n> 项建议补充 · 🔵 <n> 项表述问题
- 结论：<一句话——当前是否具备进入研发评审的条件；如不具备，卡点是什么>

## 🔴 Blocker（开发/评审前必须回答）

### [<规则ID>] <一句话标题>
- **位置**：<章节名>（第 <行号> 行附近）
- **原文**：「<逐字引用，不得改写>」
- **问题**：<为什么这是问题，一两句话>
- **请回答**：<针对该规则的具体填空问题>

（每条 Blocker 重复上述结构）

## 🟡 Warning（建议补充）
（同上结构，逐条列出）

## 🔵 Nit（表述问题）
（同上结构，可适当精简，但原文引用不可省）

## 需人工确认（工具不确定，不算硬伤）
- <位置 + 疑点 + 为什么不确定>

---
*本次启用规则：A1-A6、B1-B4、C1-C5（v1）。如需关闭某条规则，告知规则 ID 即可。*
```

## 撰写要求

1. **原文逐字引用**：每条 finding 的「原文」必须是文档中的原句，不得转述；找不到原句的质疑不允许上报。
2. **同类合并**：同一规则在多处触发，合并为一条 finding，原文处列举 2-3 个最典型的并注明"全文共出现 n 处"。
3. **空分区不省略**：某一级别为零时显式写"无"。
4. **结论只谈就绪度**：结论判断"是否可进入研发评审"，不判断产品方向对错。
5. **语气**：对事不对人，质疑针对文档不针对作者；问题说透，但不堆砌正确的废话。
