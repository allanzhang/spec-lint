# 校准日志（规则进化记录）

每次真实评审后，把用户裁决追加到本文件。规则改动据此起草，攒批经用户确认后生效。

## 隐私铁律

- 本文件**只记录规则现象与教训**，永不记录：公司名、项目名/产品名、人名、客户名、具体业务数据（金额、人日、接口名）、文档原文片段。
- 文档统一用体裁代称：「SaaS 工程 PRD」「硬件玩具 PRD」「调研/可行性文档」等。
- tests/ 语料同理：只用虚构或泛化内容（ERP、中间层等通用术语）。

## 记录格式

```
## YYYY-MM-DD · <体裁代称>（如：硬件玩具 PRD，PDF 6 页）
- <规则ID> · <FP误报/MISS漏报/级别调整/新增> · <现象（泛化描述）> · <处置> · <状态>
```

裁决类型：
- **FP**（误报）：工具报了，用户判定不是问题 → 收窄规则/加白名单/降级别
- **MISS**（漏报）：用户踩了坑但工具没报 → 新增规则或扩充模式
- **SEV**（级别）：严重度调高/调低
- 每条规则的演变在 `rules.md` 对应规则下以「校准记录」一行摘要体现，详情查本日志。

## 新规则生命周期

1. 新规则先以 🟡/🔵 或「需人工确认」身份进入 rules.md 试运行；
2. 连续在 ≥3 份不同文档中被确认为有效命中，才允许升 🔴；
3. 连续误报 ≥2 次的规则降级或删除；
4. 长期（≥10 份文档）零命中的规则进入待删除评审。
